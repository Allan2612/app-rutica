| B1 | 🟠 | El adaptador de storage puede guardar la sesión **sin `refresh_token`** | [lib/supabase/client.ts:41-56](../../src/lib/supabase/client.ts#L41-L56) | En nativo, si el JSON de sesión pasa de 3800 caracteres, solo guarda `{access_token}`. Una sesión de Supabase con `user_metadata` (nombre, apellidos, teléfono, rol) e `identities` puede superar ese tamaño. Al reabrir la app o al expirar el token (1 h) no se puede refrescar y el usuario queda deslogueado. La premisa del código ("límite de 2048 bytes de SecureStore") no aplica: se usa **AsyncStorage**, que no tiene ese límite. **Fix:** pasar `storage: AsyncStorage` directo (es lo que recomienda Supabase para Expo) y borrar el adaptador. |
| B2 | 🟠 | `hasLocation` / `hasCoordinates` del `locationStore` quedan congelados | [store/locationStore.ts:75-90](../../src/store/locationStore.ts#L75-L90) | Zustand mezcla el estado con `Object.assign`, que **evalúa los getters** y los convierte en valores fijos (calculados con el estado *anterior*). Después del primer `setLocation`, `hasLocation` vale `false` para siempre. `useLocationDetection` depende de él (`if (storedLocation && hasLocation)`), así que nunca se inicializa desde el store. **Fix:** derivar en el componente (`useLocationStore(s => !!s.location?.province …)`) o con funciones selectoras. |
